# Phase 6: decision guidance and comparison

Implemented 14 November 2026 IST. Application/engine/rules/services **0.6.0**, core catalog **0.4.0**. This phase implements the first product improvements from the [repository comparison](REPOSITORY_COMPARISON.md); it does not assert that missing vendor contracts, tenant facts or independent architecture review have been obtained.

## Delivered

- `review_actions`: affected fields/components, evidence requests, next actions, resolution gates and scoped primary references. Evidence gaps, network/deployment conflicts and pricing-model limits remain distinct. P2's OTP and payment blockers are independent. No free-text attestation bypass was added.
- `integration_reviews`: federation, database reuse and inventory tasks for existing systems, including private connectivity, ownership, claims, licensing, recovery and cost boundaries. No automatic migration, reuse credit or assumed SQL license entitlement. A recognized SQL Server 2019 instance receives the extended-support context, rather than an EOL finding.
- A distinct **Central India App Service Environment v3 Linux Iv2** host, PostgreSQL Flexible Server with in-region backup scope, and Blob LRS storage. Shared App Service and unreviewed countries retain their coverage limits. A fixed catalog region follows this SKU even when no residency is requested.
- Public primary Linux I1 v2 consumption meter: **USD 0.395/instance-hour**, captured from Microsoft's retail API. Compute rounds reference CPU needs to whole two-vCPU instances while preserving the replica floor. [Exact record](research/azure-ase-price.json). Other resource/capacity rates remain planning proxies.
- `plan_comparison`: up to three complete candidates after compatibility, service, control and cost evaluation; includes selected/tie status, score difference, core and supporting choices, regions, cost, operating burden and retained constraints. No independently mixed layers or confidence probabilities.
- `cost_groups`: infrastructure/operations versus payment/message activity, reconciled in cents. `cost_sensitivity`: one input at a time on the fixed selected plan, with supplied/assumed origin, trial values, bands/deltas and explicit model limits. Trials never edit requirements or rerank plans. Supplying an unknown count changes its uncertainty range as well as its upper volume.
- Browser panels for these records; price units, rates and primary links; keyboard-operated disclosures and a readable, keyboard-scrollable mobile sensitivity table. Draft/export stale protection remains enforced.
- JSON Schema and semantic checks for the new extensions, generated types, deterministic metadata and negative/mutation coverage. Older standard recommendation objects remain accepted; 0.6.0 engine outputs require all five extension arrays.

At 360 px, document width remains 360 px and the sensitivity table scrolls within its own container with a readable first column. This is a focused QA pass, not a full accessibility or cross-browser certification.

## Remaining evidence and product limits

P1 remains `ok`, P3 `ok_with_warnings`, and P2/P4/P5/P6 remain `infeasible`. The Azure core gap is narrower; P5 still lacks tenant-specific identity data-flow evidence. Phone delivery and payments still need end-to-end country/product/merchant scope. Razorpay was reviewed as a candidate but was not silently approved or substituted. An India provider address or app region does not settle all flows.

Integration reviews are concrete design tasks, not implemented application adapters or a priced existing-resource reuse plan. Cost experiments improve transparency; load-test sizing, full regional quote calibration and independent quality review remain open. Preference changes can be explored by editing priorities and reevaluating; an automated preference-sensitivity view is not delivered. No evaluation-only relaxed-requirement proposal mode is enabled.
