# Release 0.9.1: GDPR placement and JSON import recovery

GDPR plus `data_residency: none` now prefers source-backed EU compute AND database placement among complete feasible plans before language, budget and weighted ranking. It never changes explicit provider/deployment/residency inputs or assumes that an unknown existing database is in the EU. Missing EU database coverage retains other feasible plans. Non-EU/unknown placement carries `GDPR_CROSS_BORDER_REVIEW` at critical severity, requiring applicable processor DPAs, a Chapter V transfer mechanism and scoped assessment. Reviewed EU placement carries critical `GDPR_DATA_FLOW_REVIEW`: CDN, identity, logs, backups, remote access and subprocessors still require review.

This is a conservative architectural preference, not a claim that GDPR prohibits all non-EU processing. Primary source: [European Commission transfer rules](https://commission.europa.eu/law/law-topic/data-protection/international-dimension-data-protection/rules-international-data-transfers_en); catalog source `gdpr-transfers` records its scope. No agreement or legal compliance is inferred.

Unchanged P3 public input now selects Fly Frankfurt `fra` and Supabase `eu-central-1`. Infrastructure is USD291.90–583.02 with the existing conservative Frankfurt price allowance. Other five public cases retain their complete decision traces, regions, infrastructure bands and warnings, compared against the retained 0.9.0 outputs in `evaluation/gdpr-regression.json`. All outputs are generated by the engine.

The frontend no longer leaves a stale import error above successful results after cancelling or navigating. Editing JSON or choosing a new file clears the old error. Syntax failures identify line/column when available and give trailing-comma or straight-quote guidance without echoing the document. A UTF-8 BOM or one enclosing JSON code block is accepted; malformed JSON is not repaired. Parsed but incomplete scenario objects continue to get field-level validation.

403 tests passed after the GDPR rule; the JSON parser/recovery additions bring the final suite to 405 across 16 files. Native tooling has 22 tests. Sixty stress cases retain 57 stacks and three expected conflicts, with deterministic repeat/CLI --no-llm checks. Real browser evidence covers import failure/cancellation/editing, code-block import, actual fixture-file batch evaluation, exports, GDPR notes, keyboard focus and scoped narrow layouts.

Lifecycle retrieval observations are retained observations of unchanged URLs, rebound only after checking each observed source URL against the extended registry. They are not new fetches of the new GDPR reference or semantic/legal approval.

Drive uploads/sharing and Unstop submission were explicitly excluded by the user's latest instruction. No online submission is claimed.

## Navigation follow-up

Route changes previously scrolled the old document before React committed the destination. Sidebar and field links then used zero-delay timers, exposing the workspace hero before jumping to the requested section. One navigation state now carries the route and optional section/field target. A layout effect positions and focuses the committed destination before paint. Browser history restoration is managed while the app is mounted, redundant history entries are avoided, and a stable scrollbar gutter prevents width changes between long and short views.

Two regressions failed against the old implementation and pass after the fix: scrolling observes the destination heading, and section navigation never performs an intermediate top-of-page scroll. The suite now has 407 tests. Real-browser checks cover deep-page navigation, direct Budget placement, browser Back, unchanged main-column position and all nine scoped DOM audits, including 320px layouts. Twelve sampled DOM observations per transition are recorded in evaluation/navigation-samples.json; this is not an exhaustive paint-frame/video audit. Static report captures remain the verified 0.9.1 views from commit 648cddd; the new direct-section screenshot is navigation-budget.jpg.
